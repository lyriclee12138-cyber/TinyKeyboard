# 需求文档（SRS）

> 项目：TinyKeyboard —— ESP32-S3 网页 HID 键鼠套装
> 版本：1.0 · 对应固件 1.2.3
> 更新时间：2026-11-19

---

## 1. 项目背景与目标

在很多场景下（工控机、矿机、KVM 目标机、无键鼠的服务器、应急运维），目标机器没有可用的物理键鼠，或现场不便插拔键鼠。本项目利用一块 ESP32-S3 开发板，将其模拟为免驱的 USB 键盘 + 鼠标（HID 复合设备），并通过板载 WiFi 热点提供一个手机端网页控制界面，让用户用手机即可向目标电脑输入文字、发送按键、移动鼠标。

**核心价值**：低成本（一块开发板）、免驱、即插即用、跨平台、无需在目标机安装任何软件。

**目标（Goals）**

| 编号 | 目标 |
|:---|:---|
| G1 | 插入目标电脑即被识别为标准 USB 键盘 + 鼠标，免装驱动 |
| G2 | 手机通过 WiFi 热点访问网页，无需专用 App |
| G3 | 支持文本输入、完整虚拟键盘、触控板三类操控 |
| G4 | 对中文等非 ASCII 文本提供可用的传输方案 |

**非目标（Non-Goals）**

- 不做蓝牙/有线以外的其它连接方式（本项目仅 WiFi + USB）
- 不提供鼠标绝对定位（触控板为相对位移）
- 不在目标机安装任何常驻软件（base64 解码为一次性脚本，可选）

---

## 2. 术语与缩略语

| 术语 | 说明 |
|:---|:---|
| HID | Human Interface Device，USB 人机接口设备（键鼠即属此类） |
| Boot Protocol | 键盘兼容 BIOS/UEFI 的启动协议 |
| AP | Access Point，WiFi 热点模式 |
| mDNS | 多播 DNS，用于 `.local` 主机名解析 |
| base64 | 一种把二进制/非 ASCII 文本编码为 ASCII 的编码方式 |
| 扫描码 / Scan Code | HID 键盘报告中的键位编码 |

---

## 3. 用户与使用场景

**目标用户**：需要远程/应急操控电脑的运维、开发者、DIY 玩家。

**典型场景**

1. 给没有键鼠的服务器/工控机临时输入命令。
2. 手机作为应急键鼠，救急键盘/鼠标失灵。
3. 批量向目标机录入文本（借助「输入」页粘贴发送）。

## 4. 功能需求

### 4.1 设备功能

| 编号 | 需求 | 优先级 |
|:---|:---|:---:|
| FR-01 | 上电后自动以 HID 复合设备枚举：接口 0 为 Boot 键盘、接口 1 为报表鼠标 | 高 |
| FR-02 | 键盘支持 6 键无冲（6KRO），报告 8 字节，端点间隔 1 ms | 高 |
| FR-03 | 鼠标支持相对位移 + 滚轮 + 左/中/右键（各 bit 独立） | 高 |
| FR-04 | 设备提供自定义 VID/PID 与厂商/产品字符串描述符 | 中 |

### 4.2 网络与控制界面

| 编号 | 需求 | 优先级 |
|:---|:---|:---:|
| FR-10 | 上电自动建立 WiFi AP：SSID `TinyKeyboard`，WPA2，最多 4 客户端 | 高 |
| FR-11 | 内置 HTTP 服务，提供手机端控制网页 `http://192.168.4.1/` | 高 |
| FR-12 | 支持 mDNS 主机名 `espkb.local` 访问 | 中 |
| FR-13 | 网页提供「输入 / 键盘 / 触控板」三个功能页 | 高 |

### 4.3 文本输入

| 编号 | 需求 | 优先级 |
|:---|:---|:---:|
| FR-20 | 输入页可粘贴文本并发送到目标机，单次最长 4096 字节，前端分块 | 高 |
| FR-21 | 发送速度可调（极速 1ms / 快 3ms / 中 8ms / 慢 20ms），默认极速 | 中 |
| FR-22 | 支持「发送」与「发送 + 回车」两种动作 | 中 |
| FR-23 | ASCII（含英文/数字/常见符号）直接按 US 扫描码敲入，支持 `\n`→回车、`\t`→Tab | 高 |
| FR-24 | 含非 ASCII（如中文）时整段自动 base64 编码发送，并在界面明确提示需解码 | 高 |
| FR-25 | 提供「发送 decode.py 内容」功能，把 5 行解码脚本敲进目标机 | 中 |

### 4.4 虚拟键盘

| 编号 | 需求 | 优先级 |
|:---|:---|:---:|
| FR-30 | 提供 75 配列虚拟键盘（含 F1–F12、方向键、导航键） | 高 |
| FR-31 | 支持组合键：粘滞修饰键（Ctrl/Shift/Alt/Win）+ 多指按住组合 | 高 |
| FR-32 | 退格、方向键支持长按连发 | 中 |
| FR-33 | Caps Lock 单击切换，并与主机 LED 状态同步显示 | 中 |

### 4.5 触控板

| 编号 | 需求 | 优先级 |
|:---|:---|:---:|
| FR-40 | 触控区滑动控制指针（相对位移），灵敏度 4 档可调 | 高 |
| FR-41 | 右侧窄条上下滑动触发滚轮 | 中 |
| FR-42 | 左/中/右键独立按钮，触控区不触发点击 | 高 |

### 4.6 状态与纠错

| 编号 | 需求 | 优先级 |
|:---|:---|:---:|
| FR-50 | `/status` 返回固件版本、客户端数、队列长度、USB 连接、Caps 状态、运行时长 | 中 |
| FR-51 | 自动读取主机 Caps Lock LED，发送文本前自动关闭，避免小写被翻成大写 | 高 |
| FR-52 | 队列满时返回「busy」，前端自动重试，避免丢字 | 中 |

## 5. 非功能需求

| 编号 | 类别 | 需求 |
|:---|:---|:---|
| NFR-01 | 性能 | 按键间隔最低 1 ms；FreeRTOS tick 1000 Hz；CPU 240 MHz |
| NFR-02 | 兼容性 | 目标机为 Windows/macOS/Linux 及 BIOS/UEFI，均免驱 |
| NFR-03 | 可靠性 | 多任务并发写 HID 需互斥保护；HTTP 与打字任务解耦（队列） |
| NFR-04 | 易用性 | 网页自适应手机屏幕（竖/横屏），无需安装 App |
| NFR-05 | 可维护性 | 提供 ESP-IDF 与 Arduino 两套实现；代码注释充分 |
| NFR-06 | 体积 | 应用分区 2 MB，固件 < 1 MB，启动快速 |

## 6. 接口需求

### 6.1 HTTP 接口（固件对外）

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| GET | `/` | 返回内嵌控制网页（HTML） |
| POST | `/type?d=&nl=` | 输入文本（body 为文本），`d` 速度、`nl` 是否补回车 |
| POST | `/key?mod=` | 发送单键/组合键（body 为键名，如 `enter`、`f5`、`ctrl`） |
| POST | `/mouse?dx=&dy=&wheel=&btn=` | 鼠标相对位移/滚轮/按键 |
| GET | `/status` | 设备状态 JSON |

> 返回体均为 JSON：`{"ok":1,...}` 或 `{"ok":0,"err":"..."}`，详见[开发文档](development.md)。

### 6.2 USB HID 描述符

- 设备：VID `0x046D`、PID `0xC31C`（罗技 K120）
- 接口 0：HID 键盘，Boot Protocol，端点 `0x81`，报告 8 字节
- 接口 1：HID 鼠标，报表协议，端点 `0x82`，报告 8 字节

### 6.3 电脑端解码脚本

- `decode.py`：`python decode.py b64.txt` → `decoded.txt`，仅依赖 Python 标准库。

## 7. 约束与限制

| 编号 | 约束 |
|:---|:---|
| C-01 | 键盘通道仅支持 ASCII（US 布局扫描码），中文需 base64 中转 |
| C-02 | 目标机非 US 键盘布局时，符号可能错位 |
| C-03 | 默认借用罗技 VID/PID，商用需更换自有标识 |
| C-04 | 目标板为 ESP32-S3（原生 USB OTG），ESP32 系列其它芯片不可直接复用 |

---

## 8. 验收标准

1. 插入目标电脑后，设备管理器/`lsusb` 显示键盘与鼠标两个 HID 设备，无需安装驱动。
2. 手机连热点后打开网页，可完成一次英文文本输入，目标机逐字显示正确。
3. 中文文本经 base64 发送，电脑端运行 `decode.py` 后还原一致。
4. 虚拟键盘组合键（如 Ctrl+C）在目标机生效。
5. 触控板可移动指针、滚动滚轮、点击三键。
6. 队列满载时发送不丢失、不崩溃，前端自动重试。
